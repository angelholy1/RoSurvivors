# `sync/` — 資料同步與驗證作業指南（給 AI 的極簡 SOP）

> **適用時機**：遊戲有新版本更新、或懷疑網站裝備／卡片／掉落／活動規則過時時。
> **核心省算力鐵律**：**禁止直接閱讀線上 4.6 MB 遊戲原始碼**；一律由 `diff-live.js` 產出精簡差異報告 `last-diff.md`，只改動有變動的 `data/*.js` 檔案。

---

## 標準 4 步驟（低算力模式）

### Step 1：執行線上差異比對
```bash
node sync/diff-live.js
```
完成後**只閱讀 `sync/last-diff.md`**。
- 若報告顯示 **「版本與資料均無變動」** → 直接回報使用者無須更新並結束。

### Step 2：依差異報告精準更新對應檔案
只修改報告中列出有變動的檔案（不要去讀其他無關檔案）：
- **裝備／卡片／寵物新增或修改** → 修改 `data/catalog.js`（裝備編號、名稱、部位、職業 `jobs`、詞條、插槽 `compound`）
- **關卡波次／Boss HP／蛇王機率／`M2` 掉落表變動** → 修改 `data/stages.js`
- **一轉天賦數值或一轉主動技變動** → 修改 `data/trees.js`
- **版本號、活動規則、系統更新摘要** → 修改 `index.html` 與 `data/builds.js` 頂部版號

> **二轉實裝鐵律**：檢查 `sync/last-diff.md` 的 **「二轉實裝開關偵測」** 區塊。只要二轉天賦樹／二轉主動技仍顯示「未開放」，**嚴禁**在網站新增未實裝的二轉天賦配點或技能推薦！

### Step 3：強制通過自動化驗收（必須 0 Errors）
```bash
node sync/validate.js
```
檢查項目包含：JS 語法、全站零 Unicode Emoji、一轉 50 點前置與武器／盾牌鎖定廢點、裝備職業合法性、卡片插槽（`#4172` 武器 / `#4372` 頭飾 / `#4048` 飾品）、雙手／盾牌衝突、物理誤配法寵／INT 卡。

### Step 4：鎖定新快照並回報是否需要流派分析
確認 `validate.js` 為 `0 Errors` 後，更新快照：
```bash
node sync/diff-live.js --update-baseline
```
最後檢查 `last-diff.md` 的 **「是否需要啟動 `meta/` 流派審查」**：
- 若無戰鬥變動 → 直接告知使用者「資料同步完成，無需重審流派」。
- 若有特定職系技能／天賦／`vP` 標籤變動（例如 `taekwon` 補回 `melee`）→ 告知使用者只需針對該職系執行 `meta/` 分析即可。
